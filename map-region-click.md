# Клик по карте и провал в регион (Stimulsoft Dashboards 2024.2.2)

Инструкция для парсера. Проверено на дашборде поступлений в бюджет РБ. Карта — `StiRegionMapElement`. Провал — штатный `onclick` геометрии, не самодельный POST.

## Что является кликом

В `stimulsoft.viewer.js` у фигуры карты обработчик вешается так: `i.onclick = function () { ... }`.

Внутри, для `interaction.onClick == "ShowDashboard"`:

- у карты (`StiRegionMapElement`) значение провала — `this.getAttribute("elementident")`;
- у графика значение — `this.getAttribute("elementargument")`;
- зритель сам шлёт `action: "DashboardDrillDown"` с этим значением.

Парсер должен найти узел и вызвать уже существующий `node.onclick.call(node)`. Синтетический `MouseEvent` без этого `onclick` карту не открывает. Слово «Брестская» в таблице кликать нельзя: это не геометрия карты.

## Где искать узлы

И родительский документ, и каждый `iframe.contentDocument` (если `doc.body` есть). Подписи карты читаются из фрейма, а `document.querySelectorAll` только по родителю их не видит.

Узел карты — любой элемент, у которого есть `elementident`, `elementargument` или `elementvalue`, и чей предок (до 40 уровней) имеет `elementAttributes.type`, содержащий `Map`. Если узел лежит во фрейме, то же самое проверяется у `node.ownerDocument.defaultView.frameElement`.

Атрибут читать так: свойство узла, затем `getAttribute`. Пустая строка и `sti_IsNullValue` — не значение.

## Как выбрать область

Собрать строку `elementident + elementargument + elementvalue + interactiontooltip`. Короткое совпадение лучше длинного.

Коды, которые реально стоят на контурах этой карты:

| Область | `elementident` | Не перепутать с |
|---|---|---|
| Брестская | `BrestskaiaVoblasts`, `BY-BR` | — |
| Витебская | `VitsebskaiaVoblasts`, `BY-VI` | — |
| Гомельская | `HomelskaiaVoblasts`, `BY-HO` | — |
| Гродненская | `HrodnenskaiaVoblasts`, `BY-HR` | — |
| Могилёвская | `MahiliouskaiaVoblasts`, `BY-MA` | — |
| Минская область | `MinskaiaVoblasts`, `BY-MI` | город Минск |
| Минск (город) | `BY-HM` | `Minskaia` / «Минская» |

Латиница и кириллица оба годятся: `брест`, `brest`, `витеб`, `гомел`, `homel`, `гродн`, `hrodn`, `могил`, `mahil`, `минск`. Для города Минск отбрасывать строку, если в ней есть «Минская» / `Minskaia` / `BY-MI`.

Если ни одна геометрия не совпала, взять короткий лист `text` / `tspan` / `title` внутри карты (длина до 48, без вложенных `tspan`) и подняться до 20 родителей к узлу с `onclick`. Сосед с `onclick` годится только если его собственный код совпал с областью.

`onclick` нет и подписи нет — клика нет. Не кликать первую попавшуюся фигуру.

## Как понять, что провал открылся

До клика запомнить ключ экрана. После клика ждать до 8 секунд, пока ключ сменится.

В ключ входят:

- текст карточек, индикаторов и карты (`element.text`, у карты ещё короткий `innerText`);
- короткие подписи фильтров, в которых есть «область», «ИМНС» или «Пинск».

Успех — ключ сменился. Для Бреста на экране карточки `722 087,17`, фильтр «Брестская область». Для Пинска карточки `7 220,87`, фильтр «ИМНС по Пинскому р-ну». Страна при этом выглядит иначе: четыре карточки, среди них `224 711,64` и `23 414,38`.

Ключ не сменился — область не открылась, даже если `onclick` вызвался. Повторный клик по уже открытой Брестской тоже не меняет ключ.

## Перед каждой следующей областью вернуться на страну

После провала кнопка панели с индексом 0 — это вкладка области (`BrestskaiaVoblasts`), не карта страны. `pageNumber = 0` без сброса оставляет внутри области.

Возврат:

1. `jsObject.reportParams.pageNumber = 0`.
2. `jsObject.reportParams.dashboardDrillDownGuid = null`.
3. `jsObject.postAction("Refresh")`.
4. Ждать, пока снова появятся геометрии карты или короткая подпись области.

Дальше клик следующей области. Иначе второй проход остаётся в Бресте.

## Район внутри области

Только после того, как ключ экрана сменился.

Искать в графике, сводной или таблице. Узлы карты пропускать, иначе клик снова попадёт в контур страны. Для Бреста текст `пинск` / `pinsk`. Для остальных областей — первая строка `ИМНС`. Вызвать `onclick` этой ячейки, не ячейки карты.

Пинск открыт, когда фильтр стал «ИМНС по Пинскому р-ну», а карточки стали `7 220,87 / 9 589,73 / 7 655,67`.

## Откуда брать таблицу после провала

`StiPivotTableHelper.getViewerData` часто возвращает только «Итог / Total» с нулями. Такой ответ нельзя записывать как данные и нельзя давать ему победить над нарисованной таблицей.

Источник, из которого зритель реально рисует сетку (`CreatePivotTableElementContent` → `showData(contentAttributes.data)`):

1. `elementAttributes.contentAttributes.data` — поля `cells`, `headerHeight`, `headerWidth`. Ось: `cells[колонка][строка]`.
2. Тот же объект на div виджета, у которого после `showData` заполнено `.data`.
3. Нарисованные `<table>` внутри видимого узла сводной (класс ячеек `pivotCell`). Шапка, подписи строк и числа часто лежат в разных таблицах: склеивать по строке, а не ставить друг под другом.

Брать видимый узел с этим именем (`getClientRects` шире 2px). Скрытая копия того же `PivotTableElement` на другой вкладке отдаёт нули.

Если в момент снимка сетка ещё пустая, подождать до 2,5 с и прочитать снова. `showData` ставит отрисовку в `setTimeout`.

Строка «Итог» с нулями и одинокая ячейка `25%` — не таблица области. Пустая область в этой базе значит, что данных нет. Числа других областей из кэша не подставлять.

На карте сумма и процент берутся только из собственного `elementvalue` контура или из его короткой подписи. Текст родительской группы на остальные области не копировать.
